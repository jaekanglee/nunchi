# Nunchi — Slack 대리 응답 데스크톱 앱 설계안 (v0.1)

> 작성일: 2026-10-14 · 상태: 초안 (구현 전 검토용)

## 0. 한 줄 요약

**내 Slack 계정 권한(User Token)으로 들어오는 메시지를 받고, 내 말투로 답장 초안을 쓰고, 위험도에 따라 "자동 전송 / 내 승인 후 전송 / 나에게만 알림"으로 나눠 처리한다. 결과는 요약과 대시보드로 받는다.** 이걸 macOS 데스크톱 앱(Electron)으로 만든다.

## 1. 가능성 판단

| 항목 | 가능 여부 | 근거 / 조건 |
|---|---|---|
| 내게 오는 메시지 실시간 수신 | ✅ 가능 | Slack App + **User Token 이벤트 구독**(`message.im`, `message.mpim`, `message.channels`, `message.groups`) + **Socket Mode**. 공개 서버 없이 로컬 앱에서 웹소켓으로 받음 |
| "나로서" 답장 | ✅ 가능 | User Token(`xoxp-`) + `chat:write` user scope로 `chat.postMessage`를 호출하면 내 이름과 아바타로 올라감. 스레드 답장은 `thread_ts` |
| 링크를 주면 그 스레드에 답장 | ✅ 가능 | permalink에서 `channel`/`ts`를 파싱한 뒤 `conversations.replies`로 맥락을 읽고 답장 |
| 내 과거 메시지로 말투 학습 | ✅ 가능 | `search.messages` 쿼리 `from:@me`로 내 메시지 수집. 파인튜닝은 필요 없고 **스타일 가이드 + few-shot 검색(RAG)**으로 충분 |
| 요약 / 대시보드 | ✅ 가능 | 로컬 SQLite에 이력을 쌓고 앱 안에서 렌더링 |
| 회사 워크스페이스 앱 설치 | ⚠️ **최대 블로커** | 회사 Slack은 보통 앱 설치에 **관리자 승인**이 필요함. user scope `*:history`와 `search:read`는 민감 권한이라 반려될 수 있음 |
| 회사 보안정책 | ⚠️ 확인 필요 | 사내 대화를 외부 LLM API(Anthropic)로 보내는 것이 사내 정책상 허용되는지 확인해야 함 |
| Slack API 약관 | ⚠️ 확인 필요 | 2025년 Slack API 약관 개정으로 API로 얻은 데이터의 LLM **학습** 사용이 제한됨. 이 설계는 학습이 아니라 프롬프트 맥락으로만 쓰지만, 사내 법무/보안팀 확인을 권장함 |
| API Rate limit | ✅ 대체로 OK | 2025년부터 비마켓플레이스 앱의 `conversations.history/replies`가 강하게 제한됐지만, **자기 워크스페이스에만 설치하는 내부 앱은 예외**. 개인 용도 트래픽이면 문제없음 |
| 노트북이 꺼져 있을 때 | ❌ 불가 | 데스크톱 앱이라 앱이 꺼지거나 잠자기 상태면 이벤트를 놓침. 깨어날 때 catch-up으로 보완(§4.6). 24시간 응답이 필요하면 나중에 코어만 서버로 분리 |
| "티 안 나게" | ⚠️ 부분적 | 텍스트 말투는 상당히 비슷하게 맞출 수 있음. 하지만 **응답 속도**(즉답), 타이핑 표시 없음, 모르는 맥락에 대한 그럴듯한 오답이 가장 크게 티 나는 지점 → §5에서 다룸 |

### 쓰지 말아야 할 방식: Slack 데스크톱 클라이언트 자체를 후킹

Slack 데스크톱(Electron) 앱에 코드를 주입하거나, 브라우저 세션 토큰(`xoxc-`/`d` 쿠키)을 빼서 쓰는 방식도 기술적으로는 가능하다. 하지만 다음 이유로 **배제한다.**
- Slack 약관 위반이고, 회사 보안 관제(DLP/EDR)에 걸리면 계정 정지나 징계 사유가 될 수 있음
- Slack 클라이언트가 업데이트될 때마다 깨짐
- 공식 API로 같은 기능이 다 되므로 얻는 이득이 없음

→ **"후킹" = 공식 이벤트 구독(Socket Mode)으로 구현**한다.

## 3. Slack App 설정

**하나의 Slack App**에 User Token과 Bot Token을 같이 둔다.

- **User Token scopes** (나로서 읽고 쓰기)
  - `im:history`, `mpim:history`, `channels:history`, `groups:history` — 메시지/스레드 읽기
  - `search:read` — 내 과거 메시지 수집
  - `chat:write` — 나로서 전송
  - `users:read` — 상대 이름/관계 식별
- **User event subscriptions**: `message.im`, `message.mpim`, `message.channels`, `message.groups`
- **Bot Token** (선택): 나에게 승인 요청 DM을 보낼 때 사용. 데스크톱 알림만 쓰면 생략 가능
- **App-level Token** (`xapp-`, `connections:write`): Socket Mode 연결용
- 배포 범위: **내 워크스페이스에만 설치** (마켓플레이스 미배포 → 내부 앱 rate limit 적용)

## 4. 기능별 설계

### 4.1 말투 학습 (Persona Store)

**목표**: 파인튜닝 없이 "나처럼 쓰는" 프롬프트 재료를 만든다.

1. **수집 (공개 채널만)**: `search.messages?query=from:@me&sort=timestamp`로 최근 6~12개월치 내 메시지를 페이지 단위로 가져온 뒤, 결과의 `channel.is_channel && !is_private`인 것만 남긴다. DM과 비공개 채널은 학습에 쓰지 않는다.
   - 이름 문자열 검색(`"홍길동"`)이 아니라 `from:@me`를 쓴다. 이름 검색은 남이 나를 언급한 메시지까지 섞여 들어오기 때문
2. **대화 쌍 만들기**: 각 내 메시지의 직전 상대 메시지(또는 스레드 부모)를 `conversations.replies`로 붙여 **(상대 발화 → 내 답)** 쌍을 만든다.
   - 주의: 공개 채널 말투는 DM보다 격식체에 가까울 수 있다. DM 답장이 실제보다 딱딱하게 나오면 승인 큐에서 고친 수정본이 few-shot으로 쌓이면서 보정된다(5번)
3. **분석 산출물**
   - `style_guide.md`: Claude가 샘플 수백 개를 보고 정리한 규칙. 문장 길이, 종결어미("~요"/"~넵"/"~ㅇㅇ"), ㅋㅋ/ㅎㅎ 빈도, 이모지·리액션 습관, 오타·띄어쓰기 습관, 맞춤법을 일부러 틀리는지, 줄바꿈 습관 등
   - `relationships.json`: 상대별 존댓말/반말, 친밀도, 평균 응답 길이. 예) `{ "U123": { "name": "김OO", "register": "반말", "tone": "장난" } }`
   - **few-shot 인덱스**: 대화 쌍을 임베딩해서 저장 → 새 메시지가 오면 비슷한 상황에서 내가 실제로 한 답 5~10개를 검색
4. **링크 사전** (`links.yaml`): "내가 자주 주는 링크"를 직접 등록한다. 예) `배포 가이드: https://...`, `휴가 신청: https://...`. 답장 생성 시 이 사전에 있는 링크만 쓸 수 있게 하고, **사전에 없는 URL 생성은 금지**한다.
5. **갱신**: 내가 승인 큐에서 초안을 수정해서 보내면, 그 수정본을 few-shot 데이터에 추가한다(사용할수록 정확해짐).

### 4.2 처리 대상 (Router / Filter)

들어온 이벤트 중 **아래만 처리**하고 나머지는 무시한다.
- 나에게 온 DM / 내가 포함된 그룹 DM
- 채널에서 나를 `@멘션`한 메시지
- 내가 참여한 스레드의 새 답글
- (수동) 내가 앱에 붙여넣은 **permalink**

**반드시 제외할 것**
- 내가 보낸 메시지(무한루프 방지: `event.user === me`이거나 이 앱이 보낸 메시지)
- 봇 메시지, 채널 join/leave 같은 subtype
- 설정의 **차단 목록**(대표, 직속 상사, 인사팀 채널 등은 항상 escalate만)

#### 감시 스레드 (Watched Thread)

멘션이나 링크는 **시작점**일 뿐이다. 한번 감시 대상이 된 스레드는 그 뒤로 나를 다시 멘션하지 않아도 계속 지켜본다.

1. **감시 등록**
   - 링크를 붙여넣으면: 그 순간 본문과 스레드 전체를 읽고 감시 목록에 넣는다
   - 자동 모드에서 나를 멘션하면: 그 본문이나 스레드를 자동으로 감시 목록에 넣는다
2. **감시 중 동작**: 감시 스레드에 새 답글이 오면 분류 단계에서 먼저 **"내가 답할 차례인가?"**(`needs_my_reply`)를 판단한다. 나한테 묻는 말이거나 내 답을 기다리는 흐름일 때만 답장 단계로 넘어가고, 아니면 맥락만 쌓는다
3. **감시 해제**: 내가 직접 끄거나, 일정 기간(기본 3일) 새 답글이 없으면 자동으로 해제한다

#### 채널별 / 글별 ON·OFF

| 단위 | 설정 | 예시 |
|---|---|---|
| 채널 | ON / OFF / 초안만 | `#장애대응`은 OFF, `#잡담`은 자동 |
| 본문 글(스레드) | ON / OFF / 초안만 | 특정 스레드만 끄기 |

우선순위: **글 설정 > 채널 설정 > 전역 모드**. 앱의 감시 목록 화면과 트레이 메뉴에서 바꾼다.

> 제약: Slack user event는 **내가 멤버인 채널**의 메시지만 보내준다. 내가 들어가 있지 않은 채널의 링크를 주면 이벤트가 오지 않으므로, 그 스레드는 `conversations.replies`를 주기적으로 조회(폴링)해서 감시한다.

### 4.3 답장 생성 (Responder)

```
[1] 분류 (Haiku)
    입력: 메시지 + 스레드 맥락 + 상대 정보
    출력: { needs_my_reply: bool, category, risk_score(0~100), needs_facts_i_dont_know: bool, reason }
    needs_my_reply가 false면 여기서 멈춘다 (감시 스레드의 맥락으로만 저장)
    category: 인사/잡담 | 단순확인·리액션 | 링크요청 | 일정조율 | 정보질문 | 업무지시·결정 | 장애·긴급 | 민감(인사·평가·돈·법무·갈등)

[2] 생성 (Sonnet)
    system: style_guide + 상대별 관계 + 링크 사전 + 금지 규칙
    context: 스레드 전체 + few-shot 5~10개
    output: { reply, confidence, used_links[], uncertain_points[] }

[3] 자체 점검 (Haiku)
    - 내가 모르는 사실을 지어냈는가?
    - 약속(일정, 마감, 승인)을 했는가?
    - 말투가 style_guide와 어긋나는가?
```

**금지 규칙(하드 코딩)**
- 모르는 사실을 단정하지 않는다 → "확인해보고 말씀드릴게요"처럼 내 평소 표현으로 보류한다
- 일정, 마감, 금액, 승인, 동의 같은 **약속은 자동으로 하지 않는다**
- 링크 사전에 없는 URL은 만들지 않는다

### 4.4 정책 엔진 (자동 / 승인 / 알림)

**운영 모드는 두 개의 스위치로 나뉜다** (트레이 메뉴와 설정 화면에서 전환).

**① 수신 모드: 무엇을 처리할지**

| 수신 모드 | 처리 대상 |
|---|---|
| **ON (자동 감지)** | DM, 그리고 나를 멘션한 본문이나 스레드를 자동으로 감시 목록에 넣고 처리. 링크로 등록한 스레드도 처리 |
| **OFF (링크 전용)** | 자동 감지는 하지 않고, 내가 링크로 등록한 스레드만 처리 |

**② 전송 모드: 처리한 걸 어떻게 보낼지**

| 모드 | 동작 |
|---|---|
| **초안 모드** | 모든 답장은 승인 큐로 간다. AUTO 판정이 나와도 전송하지 않고 초안으로만 둔다 |
| **자동 모드** | 아래 표의 AUTO 조건을 만족하면 자동 전송, 나머지는 승인 큐 |

- 모드는 **전역 기본값** + **상대/채널별 덮어쓰기**로 설정한다. 예) 전역은 자동, 팀장 DM은 초안
- 링크 모드(permalink 붙여넣기)는 붙여넣을 때 [초안만] / [바로 전송]을 고른다
- **ESCALATE는 모드와 상관없이 항상 적용**된다. 자동 모드여도 장애나 민감한 건은 답하지 않고 알림만 보낸다

| 결과 | 조건 (초기값, 설정에서 조정) | 동작 |
|---|---|---|
| **AUTO** 자동 전송 | category ∈ {잡담, 단순확인, 링크요청} AND risk < 20 AND confidence ≥ 0.8 AND 상대가 허용 목록에 있음 | 지연 후 전송, 대시보드에 기록 |
| **APPROVE** 승인 후 전송 | 그 외 일반 업무 | 초안을 승인 큐에 넣고 macOS 알림. [보내기] [수정] [무시] |
| **ESCALATE** 나에게 알림만 | 장애·긴급, 민감, 업무지시·결정, 차단 목록 상대, `needs_facts_i_dont_know` | 답장 안 함. 즉시 소리 있는 알림 + 요약과 추천 대응 |

**처음 2주는 AUTO를 끄고 APPROVE만 운영**한다. 승인 큐에서 "수정 없이 보낸 비율"이 카테고리별로 90%를 넘으면 그 카테고리만 AUTO로 승격한다. 대시보드에서 이 수치를 보여준다.

### 4.5 티 안 나게 하기 (Sender)

| 티 나는 지점 | 대응 |
|---|---|
| 즉답 | 내 과거 응답 지연 분포를 학습해서 그 범위 안에서 랜덤 지연 (예: 1~8분) |
| 연속으로 여러 메시지를 보내는 습관 | 내가 평소에 끊어 보내는 편이면 2~3개로 쪼개서 전송 |
| 리액션만 하는 습관 | "넵 확인"류에는 메시지 대신 `reactions.add`(👍, 👀)로 처리 (`reactions:write` user scope 추가) |
| 근무시간 외 즉답 | 퇴근 후나 회의 중(캘린더 연동은 v2)에는 AUTO를 멈추고 다음날 아침 승인 큐로 넘김 |
| 같은 상대와 긴 핑퐁 | 한 스레드에서 AUTO 연속 2회를 넘으면 강제로 APPROVE로 전환 |

### 4.6 앱이 꺼져 있었을 때 (Catch-up)

- 앱 시작이나 잠자기 해제 시 `last_seen_ts` 이후 DM/멘션을 조회해서 미처리분을 큐에 넣는다
- 오래된 메시지(예: 2시간 이상)는 **자동 전송하지 않고** APPROVE로 넘긴다. 늦은 답이 자동으로 나가면 오히려 어색함

### 4.7 요약 (Summarizer)

- **즉시**: ESCALATE 건마다 3줄 요약 + 추천 대응
- **주기**: 점심과 퇴근 전(설정 가능)에 다이제스트
  - 내가 대신 처리한 대화 N건 — 상대, 한 줄 요약, 내가 보낸 답
  - 내가 직접 봐야 하는 것 — 우선순위 순
  - 내가 한 약속이나 후속 조치(TODO 후보)

### 4.8 대시보드

| 패널 | 내용 |
|---|---|
| 오늘 처리 현황 | 수신 / AUTO / APPROVE / ESCALATE 건수 |
| 승인 품질 | 카테고리별 "수정 없이 승인" 비율 추이 → AUTO 승격 판단 근거 |
| 응답 시간 | 평균 응답 지연 (나 vs 앱) |
| 상대별 | 가장 많이 대응한 사람 / 채널 |
| 이력 | 대화별 원문, 초안, 최종 전송본, diff |
| 비용 | LLM 토큰 사용량, 일별 비용 |

## 6. 안전장치 (반드시 v1에 포함)

- **킬스위치**: 트레이 메뉴 "전체 정지" 한 번으로 모든 전송 중단
- **전송 직전 재확인**: 승인 이후 스레드에 새 메시지가 올라왔으면 초안을 폐기하고 다시 생성
- **전송 로그는 삭제 불가**: 나중에 "이거 내가 보낸 거 맞나?"를 확인할 수 있게
- **루프 방지**: 내 메시지, 앱 메시지, 다른 봇 메시지는 무시
- **토큰 보관**: Keychain에만 저장, 로그에 토큰과 원문 전체를 남기지 않음

## 7. 단계별 구현 계획

| 단계 | 내용 | 검증 방법 |
|---|---|---|
| **P0. 사전 확인** | 사내 Slack 관리자에게 앱 설치 가능 여부 확인, 외부 LLM 전송에 대한 보안정책 확인 | 승인 여부 (불가하면 여기서 설계 재검토) |
| **P1. 골격** | Electron + Bolt Socket Mode 연결, DM 이벤트를 로그로 출력 | 테스트 계정에서 DM을 보내면 앱에 표시되는지 |
| **P2. 말투 학습** | `from:@me` 수집 → 대화 쌍 → style_guide / relationships / few-shot 인덱스 | 블라인드 테스트: 실제 내 답과 생성 답을 섞어서 내가 구분 가능한지 |
| **P3. 링크 모드** | permalink를 붙여넣으면 초안 생성 → 승인 → 스레드 전송 | 실제 스레드에 정상 전송 |
| **P4. 자동 수신 + 승인 큐** | 이벤트 → 분류 → 초안 → 승인 큐 / ESCALATE 알림 (AUTO 끔) | 2주 운영, 수정률 측정 |
| **P5. 요약 + 대시보드** | 다이제스트, 대시보드 패널 | 다이제스트만 보고 놓친 게 없는지 |
| **P6. AUTO 단계적 활성화** | 수정률이 낮은 카테고리부터 AUTO 승격, 지연/분할 전송 | 상대방 반응 이상 여부, ESCALATE 누락 0건 |
